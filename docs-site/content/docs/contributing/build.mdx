The Adagio documentation site is a [fumadocs](https://fumadocs.vercel.app/) project inside `docs-site/`. All content lives as MDX files under `docs-site/content/docs/`.

<Callout type="info">
**Prerequisites:** Node.js 20 or later and npm must be installed. Run `node --version` to verify.
</Callout>

## Run Locally

<Steps>
<Step>
**Enter the docs directory:**

```bash
cd docs-site
```
</Step>
<Step>
**Install dependencies:**

```bash
npm ci
```

This installs the exact versions pinned in `package-lock.json`.
</Step>
<Step>
**Start the dev server:**

```bash
npm run dev
```

Open `http://localhost:3000/docs` in your browser. Changes to MDX files hot-reload automatically — no restart needed.
</Step>
</Steps>

## Add a New Page

<Steps>
<Step>
**Create the MDX file** in the correct section directory:

```bash
# Example: a new page under architecture/
touch content/docs/architecture/my-topic.mdx
```
</Step>
<Step>
**Register the slug** in the section's `meta.json` `pages` array:

```json
{
  "pages": [
    "overview",
    "sync-engine",
    "vfs-driver",
    "e2ee-protocol",
    "my-topic"
  ]
}
```
</Step>
<Step>
**Verify the build passes:**

```bash
npm run build
```

A missing file or a slug that does not match a filename produces a build error with the exact path that is wrong.
</Step>
</Steps>

<Callout type="tip">
Always run `npm run build` before pushing documentation changes. The CI pipeline runs the same check and will block the PR if the build fails.
</Callout>

## Production Build

```bash
npm run build
```

The static output is placed in `docs-site/out/`. This is the directory deployed to GitHub Pages. To preview it locally:

```bash
npx serve docs-site/out
```

## Type Check

Run the TypeScript type checker without producing output files:

```bash
npm run typecheck
```

This is useful for catching type errors in custom MDX components or `fumadocs` configuration before committing.
