Adagio is a Rust/Tauri workspace split into eight crates. A long-running daemon process owns the sync engine and exposes a Unix domain socket; the desktop UI (Tauri + React) and the CLI both connect to that socket and exchange NDJSON IPC messages to query state and trigger actions.

## Crate Map

| Crate | Purpose |
|---|---|
| `adagio-core` | Shared domain types, sync engine (journal, reconciler, propagator), SQLite WAL journal |
| `adagio-daemon` | Long-running IPC server and sync orchestrator |
| `adagio-desktop` | Tauri + React desktop UI; communicates with the daemon over IPC |
| `adagio-cli` | `clap`-based CLI; thin IPC client that forwards commands to the daemon |
| `adagio-ipc` | Shared `DaemonRequest`, `DaemonResponse`, and `DaemonEvent` message types |
| `adagio-nextcloud` | WebDAV + Nextcloud REST API client (propfind, upload, file metadata) |
| `adagio-e2ee` | Nextcloud E2EE v2 protocol — RSA-2048, AES-128-GCM, BIP-39 mnemonic |
| `adagio-vfs` | FUSE3 on-demand virtual filesystem driver |

## IPC Flow

All communication between clients (desktop or CLI) and the daemon follows the same three-step lifecycle.

<Steps>
<Step>
**Send request** — the desktop UI or CLI serialises a `DaemonRequest` as a newline-delimited JSON message and writes it to the Unix socket.
</Step>
<Step>
**Dispatch and respond** — the daemon's IPC server deserialises the message, routes it to the appropriate handler, and writes a `DaemonResponse` back to the same connection.
</Step>
<Step>
**Receive push events** — the daemon broadcasts `DaemonEvent` messages asynchronously to all connected subscribers whenever sync state changes (file uploaded, conflict detected, pair status update, etc.).
</Step>
</Steps>

<Callout type="info">
The IPC message types are defined in `adagio-ipc` and re-exported by every crate that needs them, so there is a single source of truth for the wire format.
</Callout>
