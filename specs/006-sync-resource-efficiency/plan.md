# Implementation Plan: Sync Resource Efficiency

**Branch**: `006-sync-resource-efficiency` | **Date**: 2026-05-29 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-sync-resource-efficiency/spec.md`

## Summary

Four acceptance criteria govern this feature. Research found that three of the
four are already architecturally sound — the changes needed are small, targeted,
and individually verifiable. The root-cause analysis:

| AC | Root cause | Fix |
|----|-----------|-----|
| AC-1 (CPU ≤ 1%) | `MissedTickBehavior::Burst` can fire back-to-back cycles; no cycle-end metrics | `Skip` behaviour + `CycleMetrics` log event |
| AC-2 (No locks) | `std::fs::read()` semantics undocumented; no test | Doc comment + one concurrent-access test |
| AC-3 (Memory ≤ +20%) | `UnboundedSender<()>` has no backpressure; no RSS logging | Bound channel to 1; `MemorySampler` |
| AC-4 (≤ 3 req/s) | Retry log lacks timing fields | Two new `tracing` fields in `with_retry` |

No new crates. No database changes. No new Tauri commands. All changes confined
to `adagio-core` with one trivial caller update in `adagio-desktop`.

**Language/Version**: Rust stable 1.75+ (edition 2021)

**Target Platform**: Linux, macOS, Windows.

**Performance Goals**:
- AC-1: CPU ≤ 1% (5-min average) after 60 s idle.
- AC-3: RSS at 24 h ≤ 1.20 × RSS at 1 min baseline.
- AC-4: ≤ 3 identical network requests per second per path.

**Constraints**:
- No new crates.
- No breaking changes to the `SyncEngine` or `Journal` public traits.
- `MemorySampler::sample_rss()` must complete in < 1 ms on all platforms.

**Scale/Scope**: 4 small targeted changes across 3 files in `adagio-core`; 1
caller update in `adagio-desktop`.

## Implementation Phases

### Phase 1: Setup — ADRs

**Deliverables**:
1. `docs/adr/007-missed-tick-skip.md` — rationale for `MissedTickBehavior::Skip`
   over `Burst` (default) or `Delay`; lists the "catch-up storm" failure mode.
2. `docs/adr/008-bounded-conflict-channel.md` — rationale for capacity-1 bounded
   channel; explains why `UnboundedSender` was the prior choice and why it is
   now changed.

No code changes in this phase.

---

### Phase 2: AC-1 — CPU Idle Behaviour

**Deliverables**:
1. `runner.rs` — one line added immediately after the `interval()` construction:
   ```rust
   ticker.set_missed_tick_behavior(tokio::time::MissedTickBehavior::Skip);
   ```
2. `local.rs` — introduce `ScanStats { checksum_recomputed: usize, checksum_from_cache: usize }`
   and return it alongside the existing scan results from `scan_blocking()`.
   Increment `checksum_recomputed` at `local.rs:176,179`; increment
   `checksum_from_cache` at `local.rs:174`.
3. `cycle/mod.rs` — collect `ScanStats` from the scanner; construct and emit
   `CycleMetrics` as `tracing::debug!(path_count, checksum_recomputed, checksum_from_cache, duration_ms, "cycle complete")`.
4. `benches/idle_scan.rs` — criterion benchmark: build a 1,000-file temp dir,
   run `scan_blocking` twice, measure time of second (steady-state) run and
   assert `stats.checksum_recomputed == 0`.
5. `///` doc comments on `ScanStats`, `CycleMetrics`, and the modified `scan_blocking` signature.

**Tests** (write first — must FAIL before implementation):
- `missed_tick_skip_does_not_fire_twice_after_slow_cycle` — use
  `tokio::time::pause()` + `advance()` to simulate a cycle that takes 2×
  `scan_interval_secs`; assert the ticker fires exactly once in that window,
  not twice.
- `cycle_metrics_reports_zero_recomputed_for_unchanged_files` — run scanner on
  the same directory twice; assert second run's `ScanStats.checksum_recomputed == 0`
  and `checksum_from_cache == file_count`.

### Phase 3: AC-2 — File Locking Safety

**Deliverables**:
1. `detection/local.rs` — add `///` doc comment to `compute_checksum()`:
   > "Uses `std::fs::read()` which on Linux/macOS opens with `O_RDONLY` and
   > on Windows with `GENERIC_READ | FILE_SHARE_READ | FILE_SHARE_WRITE |
   > FILE_SHARE_DELETE`. No file descriptor is held open after return."
2. No logic changes.

**Tests** (write first — must FAIL before implementation):
- `scan_concurrent_open_file_no_lock` — spawn a `std::thread` that opens a file
  in the scan root with `std::fs::File::open` and holds it for the duration;
  concurrently run `scan_blocking()`; assert the scan returns `Ok(...)` with no
  `ErrorKind::PermissionDenied` or `WouldBlock`.

---

### Phase 4: AC-3 — Memory Stability

**Deliverables**:
1. `observability.rs` — add:
   - `pub struct MemorySample { pub rss_bytes: u64, pub baseline_rss: Option<u64>, pub growth_ratio: Option<f64> }`
   - `pub struct MemorySampler { baseline_rss: Option<u64> }` with `new()`,
     `set_baseline(rss: u64)`, `sample_rss() -> Option<u64>` (platform-specific;
     `unsafe` on Linux with `// SAFETY:` comment), `observe(&self) -> MemorySample`.
   - `observe()` emits `tracing::debug!` always; `tracing::warn!` when
     `growth_ratio > 1.15`; `tracing::error!` when `growth_ratio > 1.20`.
   - `///` doc comments on all public items.
2. `cycle/mod.rs` — create `MemorySampler` in `DefaultSyncEngine::new()`; call
   `sampler.observe()` at end of each cycle in `SyncCycle::run`; call
   `set_baseline()` after the first successful cycle completes.
3. `adagio-desktop/src/lib.rs` — change
   `mpsc::unbounded_channel::<()>()` → `mpsc::channel::<()>(1)`;
   change downstream `.send(()).await` in the propagator callback →
   `.try_send(())` with `TrySendError::Full` arm that silently drops.

**Tests** (write first — must FAIL before implementation):
- `memory_sampler_returns_nonzero_rss` — call `MemorySampler::sample_rss()`,
  assert `Some(n)` with `n > 0`.
- `memory_sampler_warn_on_growth_above_threshold` — set baseline to 100 MB,
  provide a fake RSS of 116 MB via a test-only `observe_with(rss: u64)` method,
  assert `growth_ratio == Some(1.16)` and that a `WARN` tracing event fires.
- `conflict_channel_full_does_not_block_propagator` — fill the channel (send
  one `()`), call `try_send(())` again, assert `Err(TrySendError::Full)` — no
  panic, no deadlock.
- `memory_stable_over_many_cycles` — run 500 mock scan cycles in a tight loop,
  call `sample_rss()` before and after, assert the ratio < 1.20.

---

### Phase 5: AC-4 — Retry Observability

**Deliverables**:
1. `cycle/propagator.rs` — in `with_retry()`, change the existing `tracing::warn!`
   on transient error from:
   ```rust
   tracing::warn!(attempt, "transient error; retrying");
   ```
   to:
   ```rust
   tracing::warn!(
       retry_attempt = attempt,
       delay_ms = delay.as_millis() as u64,
       "transient error — retrying after backoff"
   );
   ```
   No other changes to `with_retry`.

**Tests** (write first — must FAIL before implementation):
- `retry_log_contains_attempt_and_delay_fields` — using `tracing_subscriber`
  in-test capture (or a custom `Layer`), simulate 3 transient errors from a
  mock client; assert captured events contain `retry_attempt` with values 0, 1,
  2 and `delay_ms >= 1000` on each.
- `retry_rate_never_exceeds_3_per_second` — record `std::time::Instant` of each
  mock client call for a single path over 5 retries; assert every consecutive
  pair of calls is ≥ 333 ms apart.
