# Implementation Plan: End-to-End Encryption (E2EE)

**Branch**: `013-e2ee-encryption` | **Date**: 2026-05-31 | **Spec**: [spec.md](spec.md)

---

## Summary

Add a new `adagio-e2ee` crate implementing the Nextcloud E2EE v2.x protocol. E2EE pairs
encrypt file content (AES-128-GCM, per-file key) and filenames (inside an AES-128-GCM
metadata blob) before upload; the server stores only ciphertext. The RSA-4096 private key
is protected by a BIP-39 mnemonic via PBKDF2-HMAC-SHA256, stored on the Nextcloud server
encrypted at rest, so any device with the mnemonic can pair. Metadata writes require a
lock/counter/CMS-signed protocol mandated by v2.x.

**Key design correction from proposal**: File content uses AES-128-GCM (128-bit keys) not
AES-256-GCM, as specified in the Nextcloud E2EE RFC. Signing uses CMS/RSA-4096 not Ed25519.
See `research.md` for full rationale.

## Technical Context

**Language/Version**: Rust stable 2021 edition (existing workspace)

**New crate**: `crates/adagio-e2ee` — `E2eeProvider` trait + `NcE2eeClient` implementation

**New dependencies**:
- `rsa = "0.9"` (RSA-4096, OAEP-SHA256 key wrapping)
- `x509-cert = "0.2"` (CSR + certificate parsing)
- `pkcs8 = "0.10"` (PKCS#8 private key serialisation)
- `aes-gcm = "0.10"` (AES-128-GCM for file/metadata, AES-256-GCM for private-key wrapping)
- `bip39 = "2"` (mnemonic generation + validation)
- `pbkdf2 = "0.12"` + `hmac = "0.12"` + `sha2 = "0.10"` (KDF for mnemonic → AES key)
- `cms = "0.2"` (CMS SignedData RFC 5652 for metadata signature)
- `rand = "0.8"` (random key/nonce/salt generation — already in workspace)
- `flate2 = "1"` (gzip of inner metadata JSON before encryption)

**Storage**: Two new SQLite tables (`e2ee_account_keys`, `e2ee_folder_state`), migration 004.
Existing `SavedPair` gains `e2ee_enabled: bool` and `e2ee_account_id: Option<String>`.

**Testing**: `cargo test --workspace`; integration tests require a live Nextcloud instance
with E2EE app ≥ 2.0.

**Target Platform**: Linux, macOS, Windows (existing CI)

**Performance Goals**: Encrypt/decrypt overhead ≤ 100 ms per file up to 10 MB.

**Constraints**: RSA private key never written to disk plaintext; mnemonic never logged.

## Key Design Decisions

### `E2eeProvider` trait (adagio-e2ee/src/lib.rs)

```rust
#[async_trait]
pub trait E2eeProvider: Send + Sync + 'static {
    async fn is_initialised(&self, account_id: &AccountId) -> Result<bool, E2eeError>;
    async fn init(&self, account_id: &AccountId) -> Result<String, E2eeError>; // returns mnemonic
    async fn pair(&self, account_id: &AccountId, mnemonic: &str) -> Result<(), E2eeError>;
    async fn encrypt_file(&self, pair_id: &PairId, filename: &str, mimetype: &str,
                          plaintext: &[u8]) -> Result<(Vec<u8>, String, E2eeFileEntry), E2eeError>;
    async fn decrypt_file(&self, pair_id: &PairId, uuid: &str,
                          ciphertext: &[u8]) -> Result<Vec<u8>, E2eeError>;
    async fn sync_metadata(&self, pair_id: &PairId) -> Result<E2eeMetadata, E2eeError>;
    async fn commit_metadata(&self, pair_id: &PairId,
                             metadata: &E2eeMetadata) -> Result<(), E2eeError>;
    async fn status(&self, pair_id: &PairId) -> Result<E2eeStatusDto, E2eeError>;
}
```

### E2EE sync path in cycle/mod.rs

```
E2EE pair sync cycle:
  1. sync_metadata() → decrypt outer + inner metadata, load file map
  2. local scan (existing detection/local.rs — unchanged)
  3. For each new local file:
       a. encrypt_file()
       b. WebDAV PUT uuid-named ciphertext
       c. Add E2eeFileEntry to in-memory metadata
  4. For each remote-new entry (uuid in metadata, not in journal):
       a. WebDAV GET uuid ciphertext
       b. decrypt_file()
       c. Write plaintext to local_root/filename
  5. commit_metadata() → lock + PUT signed metadata + unlock
```

### Lock/counter invariant

`e2ee_folder_state.counter` is the last committed counter. Every write increments it by 1
and sends `X-NC-E2EE-COUNTER: counter+1`. If the server rejects with 409, the client must
re-fetch metadata (the counter was bumped by another device), merge, and retry once.

### Metadata version gate

`run_e2ee_sync` reads `metadata_version` from the response JSON. If the version string is
neither `"2.0"` nor `"1.0"`, return `E2eeError::UnsupportedMetadataVersion(ver)`.
v1.0 → download + decrypt only; block uploads with `E2eeError::LegacyMetadataReadOnly`.

### Private key memory hygiene

- RSA private key bytes are zeroed via `Zeroize` after use in each operation.
- `E2eeKeySet` implements `ZeroizeOnDrop`.
- The PBKDF2-derived AES-256 key is in a `Zeroizing<[u8; 32]>` wrapper.

### E2EE-aware propagator

The existing `Propagator` in `cycle/propagator.rs` gains a `with_e2ee(provider, pair_id)`
builder variant. When E2EE is active, `upload_single` routes through
`provider.encrypt_file()` before PUT, and `download_file` routes through
`provider.decrypt_file()` after GET. This keeps the non-E2EE path unchanged.
