# Implementation Plan: Linux System Tray Support

**Branch**: `015-linux-tray-support` | **Date**: 2026-06-03 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/015-linux-tray-support/spec.md`

## Summary

The tray popover UI (`TrayPopover.tsx`) and its Rust click-handler (`lib.rs`) already exist, but the feature is non-functional on Linux for three reasons: (1) the `"tray"`-labeled Tauri window is missing from `tauri.conf.json`, (2) the tray icon uses a full-colour app icon instead of the required monochrome PNG, and (3) the popover Y-position logic assumes a top panel, which breaks on KDE's default bottom taskbar. This plan adds the missing window config, fixes icon and position handling, and adds the `get_platform` command to display correct keyboard shortcut labels on Linux.

## Implementation Phases

### Phase A — Tests First (T001–T005)

Write failing tests before any implementation.

**T001** — `get_platform` returns the correct platform string
```rust
// crates/adagio-desktop/src/commands/mod.rs
#[test]
fn get_platform_returns_linux_on_linux() {
    let p = get_platform();
    assert_eq!(p, "linux");  // only meaningful in Linux CI
}
```

**T002** — Position helper: top-panel path
```rust
// crates/adagio-desktop/src/lib.rs (or lifecycle.rs)
#[test]
fn compute_tray_position_top_panel() {
    let pos = compute_popover_position(
        (760_f64, 30_f64),   // click near top of 1080p screen
        (380, 520),          // win size
        1920, 1080,          // screen size
    );
    // y should be BELOW the click (top panel)
    assert!(pos.1 > 30, "popover should be below top panel");
    assert!(pos.0 >= 0);
}
```

**T003** — Position helper: bottom-panel path
```rust
#[test]
fn compute_tray_position_bottom_panel() {
    let pos = compute_popover_position(
        (760_f64, 1050_f64),  // click near bottom
        (380, 520),
        1920, 1080,
    );
    // y should be ABOVE the click (bottom panel)
    assert!(pos.1 < 1050, "popover should be above bottom panel");
}
```

**T004** — Position helper: Wayland fallback (position at origin)
```rust
#[test]
fn compute_tray_position_wayland_fallback() {
    let pos = compute_popover_position(
        (0_f64, 0_f64),       // Wayland compositor returns 0,0
        (380, 520),
        1920, 1080,
    );
    // Falls back to top-right corner
    assert_eq!(pos.0, 1920 - 380 - 16);
    assert_eq!(pos.1, 48);
}
```

**T005** — TrayPopover renders "Ctrl+" modifier on Linux (frontend)
- Add to `TrayPopover.test.tsx`: mock `get_platform` to return `"linux"`, assert that action row kbd text contains `"Ctrl+"`.

### Phase B — Tauri Config (tauri.conf.json)

**B1 — Add tray window**

In `crates/adagio-desktop/tauri.conf.json`, add to `app.windows`:
```json
{
  "label": "tray",
  "url": "index.html?tray",
  "width": 380,
  "height": 520,
  "visible": false,
  "decorations": false,
  "alwaysOnTop": true,
  "resizable": false,
  "skipTaskbar": true
}
```

**B2 — Fix tray icon path**

Change `app.trayIcon.iconPath` from `"icons/icon.png"` to `"icons/png-mono/adagio-icon-mono-24.png"`. Keep `iconAsTemplate: true` (harmless on Linux, required for macOS).

**B3 — Add Linux bundle dependencies**

In `bundle.deb`, add:
```json
"depends": ["libayatana-appindicator3-1 | libappindicator3-1"]
```

In `bundle.rpm`, add:
```json

```

### Phase C — Rust Backend

**C1 — Extract position helper to `lifecycle.rs`**

Add a pure function (no Tauri types, fully testable):
```rust
/// Computes the (x, y) screen position for the tray popover.
///
/// Positions the popover below the click point for top panels and above for
/// bottom panels. Falls back to top-right corner when position is (0, 0)
/// (Wayland compositors that do not expose cursor position).
pub fn compute_popover_position(
    click: (f64, f64),
    win_size: (u32, u32),
    screen_w: u32,
    screen_h: u32,
) -> (i32, i32)
```

**C2 — Update tray click handler in `lib.rs`**

Replace the inline position calculation with a call to `compute_popover_position`, using the primary monitor size from `app_handle.primary_monitor()`.

Add a guard for missing tray window:
```rust
let Some(tray_win) = app_handle.get_webview_window("tray") else {
    tracing::warn!("tray window not found — check tauri.conf.json");
    return;
};
```

**C3 — Handle missing tray host gracefully**

Wrap `app.tray_by_id(...)` call with an explicit `None` branch that logs at `WARN`:
```rust
if app.tray_by_id("main").is_none() {
    tracing::warn!("no tray icon registered — tray host may be unavailable");
}
```

**C4 — Add `get_platform()` command**

In `crates/adagio-desktop/src/commands/mod.rs`:
```rust
/// Returns the current operating system identifier.
///
/// Used by the tray popover to display platform-appropriate keyboard
/// modifier labels (⌘ on macOS, Ctrl on Linux/Windows).
#[tauri::command]
pub fn get_platform() -> &'static str {
    #[cfg(target_os = "linux")]   { "linux" }
    #[cfg(target_os = "macos")]   { "macos" }
    #[cfg(target_os = "windows")] { "windows" }
}
```

Register in `lib.rs`'s `invoke_handler`.

### Phase D — TypeScript Frontend

**D1 — Add `getPlatform` binding to `tauri.ts`**

```typescript
export const getPlatform = (): Promise<'linux' | 'macos' | 'windows'> =>
  invoke('get_platform');
```

**D2 — Update `TrayPopover.tsx` shortcut labels**

```tsx
const [platform, setPlatform] = useState<'linux' | 'macos' | 'windows'>('macos');
useEffect(() => { getPlatform().then(setPlatform).catch(() => {}); }, []);
const mod = platform === 'macos' ? '⌘' : 'Ctrl+';
```

Replace hardcoded `'⌘O'`, `'⌘B'`, `'⌘P'`, `'⌘,'` with `\`${mod}O\``, etc.
