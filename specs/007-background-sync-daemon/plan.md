# Implementation Plan: Background Sync Daemon

**Branch**: `007-background-sync-daemon` | **Date**: 2026-05-29 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/007-background-sync-daemon/spec.md`

---

## Summary

Extract the sync engine (`DefaultSyncEngine`, `PairRunner`, `SqliteJournal`,
`AccountManager`) from the Tauri desktop process into a standalone `adagio-daemon`
binary. The Tauri app becomes a thin IPC client. A new `adagio-ipc` crate holds the
shared protocol types used by both. No changes to `adagio-core` or `adagio-nextcloud`.
The React frontend and all existing DTO shapes are unchanged.

**Three new workspace members**: `adagio-daemon` (binary), `adagio-ipc` (library).
**One major refactor**: `adagio-desktop` AppState + Tauri commands → IPC forwarding.

---

## Technical Context

**Language/Version**: Rust stable 1.78+ (edition 2021)

**Primary Dependencies**:
- `adagio-core`, `adagio-nextcloud` — unchanged
- `tokio` with `full` features — `UnixListener`, `windows::named_pipe`, `signal`, `TaskTracker` already available
- `serde_json` — already in workspace; used for NDJSON framing
- `tokio-util` — already in workspace; `CancellationToken`, `TaskTracker`
- `winreg = "0.52"` — new, Windows-only, for auto-start registry write

**IPC transport**: NDJSON over `tokio::net::UnixListener` (Linux/macOS) and
`tokio::net::windows::named_pipe` (Windows). No new protocol crate.

**Storage**: No schema changes. Existing SQLite journal and config paths unchanged.

**Testing**: `cargo test` for unit + integration. All 133 existing `adagio-core` tests
and 37 `adagio-desktop` tests must continue to pass after refactor.

**Target Platform**: Linux, macOS, Windows.

**Performance Goals**:
- GUI window connects to running daemon in ≤ 1 s (SC-003)
- Daemon starts at login within 5 s (SC-002)
- Zero additional sync latency from process separation (SC-001)
- Graceful shutdown completes in ≤ 30 s (FR-007)

**Constraints**:
- `adagio-core` MUST NOT be modified (no engine changes in this feature)
- React frontend MUST NOT be modified (all DTO shapes preserved)
- All existing Tauri commands MUST remain callable with the same signatures
- Daemon spawn MUST use `std::process::Command` with detached stdio, NOT
  `tauri-plugin-shell` sidecar (which auto-kills children on parent exit)

**Scale/Scope**: 2 new crates, ~1 refactored crate, ~600 lines new Rust code.

### Phase 2: `adagio-ipc` — Shared protocol types and client

**Deliverables**:
1. `types.rs` — `DaemonRequest`, `DaemonResponse`, `DaemonEvent` enums; `serde`
   `rename_all = "snake_case"` on all variants; `///` doc comments on all public items
2. `transport.rs` — `daemon_socket_path() -> PathBuf` (platform-specific);
   `connect_rpc() -> Result<(BufReader<...>, BufWriter<...>)>`;
   `connect_subscription() -> Result<BufReader<...>>`
3. `client.rs` — `DaemonClient` with:
   - `connect_or_start(daemon_binary_path: &Path) -> Result<Self>` — try connect,
     on failure spawn daemon + retry with 5 s timeout
   - `request(req: DaemonRequest) -> Result<DaemonResponse>` — send + await response
   - `subscribe() -> broadcast::Receiver<DaemonEvent>` — returns clone of event rx
   - `connection_state() -> watch::Receiver<ConnectionState>`
   - Background task that drives the subscription stream → broadcasts to all subscribers
   - Background heartbeat (pings every 5 s; marks disconnected after 3 failures)
   - Reconnection loop: on disconnect, attempts `connect_or_start` up to 3 times with
     1 s between attempts; on 3rd failure transitions to `ConnectionState::Failed`

**Tests** (failing first):
- `daemon_request_serialises_to_snake_case` — `DaemonRequest::GetStatus` → `"get_status"`
- `daemon_event_deserialises_from_ndjson` — parse `ConflictDetected` event line
- `client_reconnect_transitions_to_failed_after_3_attempts` — mock failing server

---

### Phase 3: `adagio-daemon` — IPC server, dispatcher, events

**Deliverables**:
1. `main.rs`:
   - `#[tokio::main]` runtime
   - Single-instance guard: bind socket → if error, ping existing → exit 0 (or exit 1 if stale)
   - `tracing` initialisation (JSON output to log file + stderr)
   - Signal handling: `tokio::signal::ctrl_c()` + `SIGTERM` on Unix
   - Wire `shutdown.rs` with 30 s drain

2. `server.rs`:
   - `accept_loop(listener, state, event_tx)` — loop over incoming connections
   - `handle_rpc_connection(stream, dispatcher)` — read NDJSON lines, dispatch, write responses
   - `handle_subscription_connection(stream, event_rx)` — write events to stream

3. `dispatcher.rs`:
   - `dispatch(req: DaemonRequest, state: &DaemonProcess) -> Result<DaemonResponse>`
   - One match arm per `DaemonRequest` variant, wired to existing engine/journal methods
   - Identical to current Tauri command handler bodies (copy + adapt)

4. `events.rs`:
   - `EventBroadcaster { tx: broadcast::Sender<DaemonEvent> }`
   - `emit_conflict_detected(pending_count)`, `emit_conflict_resolved(id, pending_count)`,
     `emit_sync_status_changed(status, pair_id)`, `emit_transfer_progress(...)`
   - Replaces the current `app.emit(...)` calls in `lifecycle.rs` / `commands/conflicts.rs`

5. `shutdown.rs`:
   - `graceful_shutdown(cancel: CancellationToken, tracker: TaskTracker, journal: Arc<SqliteJournal>)`
   - Cancels all runners, waits up to 30 s via `timeout(30s, tracker.wait())`
   - WAL checkpoint: `journal.checkpoint().await`

6. `autostart.rs`:
   - `set_start_at_login(enabled: bool, daemon_path: &Path) -> Result<()>`
   - Linux: write/delete `~/.config/autostart/adagio-daemon.desktop`
   - macOS: write/delete `~/Library/LaunchAgents/com.adagio.daemon.plist` + call `launchctl`
   - Windows: write/delete HKCU `Run` registry value via `winreg`
   - `is_start_at_login_enabled() -> bool` — check presence of entry

**Tests** (failing first):
- `single_instance_rejects_second_bind` — bind socket, attempt second bind, assert error
- `dispatcher_routes_ping_to_pong` — mock DaemonProcess, dispatch Ping, assert Pong
- `dispatcher_routes_get_status` — mock engine, dispatch GetStatus, assert SyncStatusDto
- `graceful_shutdown_drains_within_30s` — spawn mock tasks, cancel, assert wait completes
- `autostart_write_creates_desktop_file` (Linux only) — write entry, assert file exists
- `autostart_delete_removes_desktop_file` (Linux only) — write then delete, assert absent

### Phase 4: `adagio-desktop` refactor — thin IPC client

**Deliverables**:
1. `state.rs` — new `AppState`:
   ```rust
   pub struct AppState {
       pub daemon: Arc<DaemonClient>,
       pub config_path: PathBuf,
   }
   ```
2. `lifecycle.rs` → `connect_or_start_daemon(config_dir: &Path) -> Result<DaemonClient>`
   - Determines daemon binary path (`current_exe()` → sibling `adagio-daemon[.exe]`)
   - Delegates to `DaemonClient::connect_or_start`
   - Returns `DaemonClient`

3. `lib.rs` setup:
   - Replace `state::AppState::new(config_dir)` with `DaemonClient::connect_or_start`
   - Subscribe to daemon events; forward `DaemonEvent::ConflictDetected` →
     `app.emit("adagio://conflict-detected", ...)` etc. (same event names as today)
   - Subscribe to `ConnectionState` watch; forward disconnected state to frontend

4. `commands/sync.rs`, `conflicts.rs`, `pair.rs`, `account.rs`, `sharing.rs`:
   - Each command body becomes: `state.daemon.request(DaemonRequest::Xyz { ... }).await?.try_into()?`
   - `prefs.rs` (`get_palette`, `set_palette`) stays unchanged — reads/writes local config file

5. `commands/daemon.rs` — NEW Tauri commands:
   - `start_daemon()` → spawn `adagio-daemon`, wait for health check
   - `stop_daemon()` → `daemon.request(StopDaemon)`
   - `set_start_at_login(enabled: bool)` → `daemon.request(SetStartAtLogin { enabled })`
   - `get_daemon_status()` → `{ running: bool, uptime_secs: Option<u64>, connection_state: String }`

6. Settings UI (React): add "Background sync" section showing daemon status + start/stop
   button + "Start at login" toggle. Calls the new Tauri commands above.

**Tests** (failing first):
- `app_state_uses_daemon_client_not_engine` — assert `AppState` has no `DefaultSyncEngine` field
- `get_status_command_forwards_to_daemon` — mock `DaemonClient`, assert `request(GetStatus)` called
- `resolve_conflict_command_forwards_to_daemon` — mock client, assert `request(ResolveConflict{...})` called
- `conflict_detected_event_forwarded_to_tauri` — mock daemon emits event, assert Tauri event fires
- `reconnecting_state_propagated_to_frontend` — mock 3 failed reconnects, assert `ConnectionState::Failed`
- `set_start_at_login_calls_daemon` — assert `request(SetStartAtLogin { enabled: true })` sent
